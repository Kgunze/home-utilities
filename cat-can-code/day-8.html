Two Kitchens, Clear Separation

Kitchen 1: NestJS

This is the cooking kitchen.

  • Cooks food
  • Decides recipes
  • Handles pricing logic
  • Checks availability
NestJS = cooks the food.

Kitchen 2: Strapi

This is the menu content kitchen.

  • Stores dish names and descriptions
  • Manages images and translations
  • Holds promotion text and CMS content
Strapi = writes the menu.

Flashcards

Role Meaning
Waiter Next.js UI takes orders, displays menu, and shows results. It does not decide anything.
Manager BFF validates, translates, splits requests, and combines results. It coordinates, not cooks.
Chef NestJS owns recipe logic, pricing, availability, and cooking rules.
Sous Chefs Services support the chef and execute smaller steps like grill, fry, or sauce work.
Cooking Stations Domain areas in the backend such as meat, salad, and drinks. Each station handles one domain.
Menu Kitchen Strapi stores dish descriptions, images, and editable content. It does not cook food.

Real Scenario

The customer says: I want a steak. Show me description and price.

  1. Waiter takes the order.
  2. Manager splits the request.
  3. Strapi returns the menu description.
  4. NestJS returns price, availability, and cooking time.
  5. Manager combines everything into one clean response.
  6. Waiter shows the final result to the customer.
Description -> Strapi
Price + availability -> NestJS

Combined result:
Grilled Steak - juicy, premium beef
Price: $25
Ready in 15 mins

What Not To Do

Mistake 1: Ask Menu Kitchen to Cook

Strapi -> calculate price

Wrong, because content storage should not own business logic.

Mistake 2: Skip Manager

Customer -> NestJS / Strapi

Wrong, because you lose control, validation, and safety.

Mistake 3: Manager Starts Cooking

BFF -> calculate pricing logic

Wrong, because now logic is duplicated outside the chef kitchen.

Security Thinking

  • Manager protects against fake orders, invalid dishes, and unauthorized requests.
  • Chef protects cooking rules, pricing rules, and business constraints.
  • Strapi stays safer because it is not directly exposed to the customer.
The manager is the safety boundary between customers and both kitchens.

Final Mental Model

Waiter -> Manager -> (Chef Kitchen + Menu Kitchen)
Role System
Waiter Next.js UI
Manager BFF
Chef Kitchen NestJS
Menu Kitchen Strapi

Final Cat Story

Cat walks in and says, I want steak.

  • Waiter takes the order.
  • Manager splits the request.
  • Chef kitchen handles the cooking logic.
  • Menu kitchen provides the description.

Cat receives a perfect dish plus a beautiful description.

Different kitchens, working together through one manager.

Ultimate Day 8 Takeaway

  • BFF is the coordinator.
  • NestJS owns cooking logic.
  • Strapi owns menu content.
  • Responsibilities should never be mixed.
Manager coordinates, Chef cooks, Menu kitchen describes.

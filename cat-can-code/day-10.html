What Is Kafka?

Apache Kafka is a system that lets services send, store, and process streams of events in real time.

Kafka is a high-speed pipeline where systems send and receive events continuously.

What Is an Event?

An event is simply something that happened in the system.

  • Order placed
  • Payment completed
  • User logged in
Systems do not only call each other. They emit events.

What Is an Event Bus?

An event bus is a shared communication channel where events flow between services.

Without an event bus

Service A -> Service B -> Service C
  • Hard dependencies
  • Fragile system
  • Hard to scale

With an event bus

Service A -> Event Bus -> Service B
                        -> Service C
                        -> Service D
Services do not talk directly. They listen to events.

Restaurant Analogy

Without an event bus

Waiter -> Chef -> Sous Chef -> Cashier

Everything is chained.

With Kafka

Order Board (Event Bus)

Waiter posts order
   ->
Chef sees it
Cashier sees it
Kitchen sees it
Kafka is the digital order board.

How Kafka Works

Step 1 - Producer

The producer sends an event, such as:

"OrderCreated"

Step 2 - Kafka

  • Stores events in topics
  • Keeps history

Step 3 - Consumer

Consumers listen and react, such as a payment service or notification service.

Producer -> Kafka -> Consumers

Why Kafka Exists

Before Kafka, systems mostly used direct API calls or simple queues.

  • Tight coupling between services
  • Data loss when messages were not stored well
  • Too many direct connections to maintain
Kafka solved decoupling, persistent event storage, and high throughput.

Origin Story of Kafka

Kafka was created at LinkedIn because LinkedIn needed to handle massive activity streams and real-time updates across many systems.

They needed one central event pipeline that many services could depend on at the same time.

The name comes from Franz Kafka, a nod to the complexity of deeply interconnected systems.

Kafka vs Traditional Queue

Feature Traditional Queue Kafka
Message storage Temporary Persistent
Replay events No Yes
Throughput Medium Very high
Consumers 1-to-1 1-to-many

Security and System Insight

Benefits

  • Loose coupling
  • Scalable design
  • Fault tolerance

Risks

  • Event explosion if too many events are introduced carelessly
  • Harder debugging across many asynchronous consumers
  • Event ordering issues in the wrong design

Mental Model Upgrade

API = request-response
Kafka = event-driven system

Before, the system felt like this:

Call this service.

Now the system feels like this:

Announce what happened.

Cat Version

Cat orders fish.

Without Kafka

  • Waiter tells chef
  • Chef tells cashier
  • Cashier tells the system

With Kafka

"Fish ordered"

Everyone reacts:

  • Chef cooks
  • Cashier prepares the bill
  • System logs the data
I do not need to tell everyone. I just announce it.

Final Day 10 Takeaway

Kafka is the backbone of event-driven systems, allowing services to communicate through events instead of direct calls.

Kafka is the event pipeline, and the event bus is the communication system for events.

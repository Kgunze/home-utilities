Topic

Onion layers through browser, Next.js, BFF, and backend.

Every request must peel through layers before it reaches the real work in the center.

Imagine an Onion

An onion has layers inside layers.

You do not jump straight to the center. You go one layer at a time.

Your App as an Onion

OUTSIDE (what user sees)

Browser
  -> Next.js (apps/web)
      -> BFF (packages/bff)
          -> Backend API

CENTER (real work happens)

This is not extra ceremony. Each layer has a job.

The Onion Restaurant

Imagine a kid says, "I want pizza."

The kid is the user, and the request must travel inward through the restaurant.

Story Role Real System
Kid asking for food Browser user
Door guard Next.js
Smart parent BFF
Kitchen Backend

Layer 1: Browser

The browser is what the user touches.

It does not cook. It does not own the business logic. It just asks.

"Give me pizza!"
The browser is the request starter, not the final authority.

Layer 2: Next.js

Next.js is the door guard. It receives the request and routes it inward.

  • Owns routing like /api/payment.
  • Acts as the structured entry point.
  • Passes the request deeper to the right place.

It does not cook either. It is the controlled doorway into the system.

Browser -> /api/payment -> Next.js route

Layer 3: BFF

This is the smartest middle layer in the story.

The BFF hears a vague request and turns it into something precise and safe.

Input from UI:
"I want something yummy"

After BFF shaping:
{ type: "pizza", size: "medium" }

That means the BFF owns:

  • Validation
  • Transformation
  • Boundary control
const parsed = OrderSchema.parse(input);

const payload = {
  type: parsed.type,
  size: parsed.size ?? "medium",
};
The BFF protects the backend from raw, messy, or unsafe UI input.

Layer 4: Backend

The backend is the real kitchen.

It takes the cleaned request and does the heavy work.

  • Database writes
  • Payment processing
  • Core business logic
{ type: "pizza", size: "medium" }

Now the backend can focus on real work instead of babysitting raw frontend input.

The Return Trip

The result does not teleport back to the user. It travels outward through the same layers.

Backend -> BFF -> Next.js -> Browser

Each layer still has a job on the way back.

  • The backend returns the result.
  • The BFF can reshape or validate the response.
  • Next.js returns it through the route boundary.
  • The browser renders it safely.

The Onion Rule

You can never skip layers. The request must move step by step.
Correct Why
Browser -> Next.js -> BFF -> Backend Every responsibility stays in the right place.
Backend -> BFF -> Next.js -> Browser The response stays controlled on the way back out too.

What Breaks If You Skip a Layer

Skip the BFF

Browser -> Backend

Then the user can send raw values directly.

{ amount: 1 }

instead of the safe, validated structure you expected.

  • No validation boundary
  • Less control over shaping data
  • Higher risk of broken logic or abuse

Skip Next.js

Browser -> BFF directly

That makes the entry point messy and harder to control.

  • You lose a clean routing boundary.
  • You weaken structure and ownership.
  • The app becomes harder to scale and reason about.

Memory Trick

Every request must peel through layers before reaching the center.

Final Kid Sentence

You are not allowed to talk to the kitchen directly. You must go through the door and the parent first.

CTO Insight

This onion architecture gives you three powerful things:

  • Security boundary: raw user input does not hit the backend untouched.
  • Control point: the BFF becomes the place where UI-facing decisions stay consistent.
  • Data shaping layer: each layer can translate data for the next one cleanly.
apps/web -> packages/bff -> backend

That is why this architecture is correct and scalable by design.

Final Summary

The browser asks, Next.js routes, the BFF validates and shapes, the backend does the real work, and the whole system stays safe because nobody skips the layers.

One Sentence to Remember

An app with good architecture is like an onion: each layer protects the next one.
